# Agentic Scheduling Platform — Engineering Blueprint

This repository blueprint defines the engineering workflow, initial architecture, requirements baseline, delivery roadmap, and decision-record process for a professional online appointment-booking platform.

## Product direction

Build a multi-provider scheduling platform inspired by products such as Cal.com and TinyCal. Customers discover providers and book appointments; providers publish services, prices, availability, and booking policies; platform administrators operate and govern the platform.

## Technology baseline

- Frontend: Vue 3, TypeScript, Vite, Vue Router, Pinia.
- Backend: Python, FastAPI, Pydantic, SQLAlchemy 2.x.
- Database: SQLite for local development and fast unit-level tests; PostgreSQL is the production database and the authoritative integration/concurrency-test database.
- Migrations: Alembic.
- API contract: versioned REST API under `/api/v1`, OpenAPI generated by FastAPI.
- Testing: TDD; pytest for backend, Vitest and Vue Test Utils for frontend, Playwright for end-to-end tests.
- Initial deployment: a modular monolith. Do not introduce microservices without an approved ADR and measurable need.

## Documents

- `AGENTS.md`: mandatory instructions for AI coding agents and human contributors.
- `Task-List.md`: project-wide delivery queue and feature-intake gate.
- `docs/ARCHITECTURE.md`: architecture and technical design.
- `docs/SRS.md`: product requirements, roles, journeys, and acceptance criteria.
- `docs/ROADMAP.md`: phased delivery plan and release gates.
- `docs/adr/`: architecture decision records.
- `docs/templates/`: reusable feature and ADR templates.

## Non-negotiable workflow

No feature implementation starts until its task is registered in `Task-List.md`, its `SPEC.md` and `PLAN.md` exist, acceptance criteria are testable, and relevant ADRs have been recorded or explicitly deemed unnecessary. Follow Red → Green → Refactor.
